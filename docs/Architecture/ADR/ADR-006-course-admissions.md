# ADR-006 — Student self-registration and course admission

Status: implements Owner policy decisions confirmed 30/10/2026 in ENROLL-01 (immediate login; course application; reviewer selects class; approval for old and new students).

Identity creates ACTIVE accounts with STUDENT only, reusing scrypt/session/cookie boundaries. No email verification or delivery is introduced. Login identifier is email for new signup; existing identifiers/passwords are unchanged. Registration requires the configured SPA Origin and permitted Fetch Metadata. Since nginx is a shared peer, per-email+peer limit is combined with a bounded global signup budget; arbitrary forwarded headers are never trusted.

Admissions is a module in the existing monolith. CourseApplication records the applicant, course, terminal decision, reviewer, destination class, timestamps and optional reason. A partial unique index permits at most one PENDING/APPROVED request per student/course. Terminal requests remain history, so cancel/reject followed by reapply creates a new row. Decision compare-and-set and class membership upsert share a transaction. A class may serve multiple courses; approval explicitly records that course/class association. Existing roster membership alone does not authorize a course.

ADMIN reviews any application and chooses any existing class. TEACHER reviews only courses they author and chooses only classes they own. Current roles are server-derived by authentication/RBAC. This matches current ownership data; separate co-teaching/delegation is outside this task.

Course title/description metadata is discoverable by authenticated students. Course bodies, lesson items, study queue, new exercise issuance, resume and first answer submission require an approved application. The unscoped item library is now authoring-only. The content visibility helper remains independent; access approval is an additional boundary. Existing student account data/results/evidence remain intact and readable by their owner; approval is not backfilled automatically. Previously issued unsubmitted sessions cannot bypass the new rule. Teacher/Admin retain existing content authoring/read permissions. The disabled standalone preview prototype is not curriculum admission.

Persistence migration11 only adds the application enum/table/constraints/indexes/FKs. Migrations1–10 remain unchanged. Encrypted backup tooling explicitly supports schema10 and schema11; it rejects other versions and does not reset or select a remote database. Before upgrading live, verify applied checksums, backup authentication, old-table data, migration success and new empty admissions table. Before migration begins, recover the prior API/Web pair on failure. Once the admission migration begins, fail closed by stopping API/Web and preserving database/evidence on failure: the old API lacks admission enforcement and is not a safe authorization fallback. Never roll back/reset the database. Any later fallback must retain the new course-access gates.

Tradeoffs: admission grants an entire course while assignments remain class-based; joining by invitation/manual roster does not bypass admission. Rejected students may resubmit, with existing per-actor limits. Queues/catalog/history queries are bounded for Local Trial. Email ownership verification, notifications, payments and revocation workflows require separate scope.
